# FABOT 투자 신호·잔고 안내 챗봇

## 서비스 소개

FABOT(F&G 기반 투자 자동화 프로젝트)의 사용자가 "오늘 F&G 신호가 뭔지", "이 종목이 쿨다운 상태인지",
"계좌 잔고가 얼마인지", "매매 전략 규칙이 뭔지"를 물어보면 답해주는 안내 챗봇입니다. **실제 매매 주문은
실행하지 않습니다** — 조회와 설명만 담당하고, 실제 매수·매도 결정과 실행은 사용자가 HTS/MTS에서 직접 합니다.

## 설계 결정 요약

- **도구를 조회용 5개(정형 조회 4개 + RAG 검색 1개)로만 제한한 이유**: 이 챗봇의 목적은 "정보를 빠르게
  확인하는 것"이지 "대신 거래하는 것"이 아닙니다. 쓰기(주문 실행) 도구를 아예 넣지 않으면, "권한을 잘못 준
  실수"라는 실패 유형 자체가 원천적으로 발생할 수 없습니다. 오늘 배운 것처럼 실제 자산에 영향을 주는
  행동(주문 실행)은 사람이 직접 승인·실행해야 하는 영역이라고 판단했습니다.
- **5번째 도구(search_strategy_rule)를 RAG/임베딩으로 설계한 이유**: 앞의 4개 도구는 "숫자 하나를
  정확히 가져오는" 정형 조회지만, "커버드콜은 언제 사?"처럼 전략 규칙 문서를 의미로 찾아야 하는 질문에는
  정형 조회가 안 맞습니다. 실제로 Qdrant+fastembed로 구현해서 테스트해봤고, 그 과정에서 진짜 실패
  사례(영어 임베딩 모델의 한국어 검색 순위 오류, 소형 모델의 답변 생성 실패)를 발견해서 설계에 반영했습니다.
  자세한 내용은 `my-agent/traces/trace-04-rag.txt` 참고.
- **권한을 읽기 전용으로만 나눈 기준**: FABOT 프로젝트 자체가 아직 "신호는 24시간 자동, 실행은 사람이 승인"
  단계에 있습니다(현재 프로젝트 로드맵과 동일). 이 챗봇도 그 경계를 그대로 따릅니다.
- **실패 뒤 행동을 "재시도 1회 + 조회 실패 안내"로 정한 근거**: 증권사 API는 실시간 조회라 일시적 실패가 흔합니다
  (오늘 KIS API 토큰 재발급 제한 등으로 실제로 겪은 문제). 무한 재시도는 API 호출 제한에 걸릴 수 있어
  1회로 제한하고, 그래도 실패하면 사람에게 "잠시 후 재시도"를 안내합니다.

## 실행하지 않은 것과 이유

- **실제 주문 실행 도구**: 이 과제 범위 밖입니다. 다음 단계(M11 해커톤 목표)에서 별도로 설계할 때는, 주문 실행
  전 반드시 사용자 확인 메시지를 한 번 더 거치는 승인 단계를 추가해야 합니다.
- **다자간 인증/권한 분리(가족 구성원별 계좌 접근 제어)**: 지금은 한 사용자가 자기 계좌만 조회한다고 가정했습니다.
  가족 구성원별로 분리된 계좌를 각자 조회하게 하려면, 사용자 인증과 계좌-사용자 매핑을 다음에 추가로 설계해야
  합니다.
- **다음에 측정할 지점**: 실제로 배포했을 때 "잘못 고름" 실패가 어느 도구 사이에서 가장 많이 나는지(특히
  get_fg_signal과 check_cooldown처럼 목적이 겹쳐 보이는 두 도구), 테스트 문항을 돌려 트레이스로 확인해야 합니다.
